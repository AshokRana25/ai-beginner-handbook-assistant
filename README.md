# AI Beginner Handbook Assistant

A local-first, single-user handbook assistant that runs on your own computer. Ask questions, inspect the supporting passages, and keep document processing and model inference local.

Built with **Python · Streamlit · Ollama · Chroma**, with a Windows 11 x64 setup guide and macOS/Linux alternatives.

**🌐 Live tutorial site:** [ashokrana25.github.io/ai-beginner-handbook-assistant](https://ashokrana25.github.io/ai-beginner-handbook-assistant/)

## AI Learning Hub tutorial website

The repository also includes an independent AI Learning Hub website in `tutorial-site/` ([open the live site](https://ashokrana25.github.io/ai-beginner-handbook-assistant/) · [read its README](tutorial-site/README.md)): **57 tutorials, 285 questions, 16 topic categories, four learning paths, and four practice projects**. All previously planned tutorials are published, with quizzes, bookmarks, browser-local progress, and light/dark themes.

To run it, install Node.js 24, then run `cd tutorial-site`, `npm ci`, and `npm run dev`. It is a static website and does not require Ollama, Python assistant credentials, or model API keys. Its own README explains tests, optional tutorial integrations, and publication. The `Tutorial site` GitHub Actions workflow verifies and packages changes; optional GitHub Pages deployment is available through its manual run after Pages is configured.

This project demonstrates retrieval-augmented generation (RAG) for handbook questions: import documents, split them into passages, index local embeddings in Chroma, and retrieve evidence for answers generated by Ollama. The Streamlit interface provides source quotations and citations, a separate general chat mode, and optional Confluence ingestion.

## At a glance

- **Two clear modes:** evidence-backed Handbook Q&A and separate General Chat.
- **Checkable answers:** strict source quotations, numbered citations, and an explicit response when the index cannot support an answer.
- **Bring authorized content:** import PDF, DOCX, HTML, or TXT exports; optionally sync the configured Confluence root with your own approved credentials.
- **Local-first boundaries:** loopback-only model endpoints, private local storage, no cloud inference, and no document content included in this repository.
- **A testable starting point:** 125 passing offline tests, including real persistent Chroma and Streamlit UI tests. Live models, live API ingestion, and Windows runtime still require validation on your computer.

This is a local demonstration, not a hosted service. It has no multi-user login or production access-control layer.

## What is included, and what is not yet verified

- Default generation model: **`qwen3:4b`**; embedding model: **`qwen3-embedding:0.6b`**. Both exact tags and the `/api/chat` / `/api/embed` APIs were verified against official Ollama documentation on 2026-10-09.
- No real handbook, company tenant URL, or page ID is bundled or pre-indexed. Configure your own approved source locally.
- Offline automated tests use clearly synthetic text, deterministic test embeddings, mocked HTTP/model replies, and **real persistent Chroma**. They do not establish live Qwen3 quality or performance on your laptop.
- Live Ollama and Confluence end-to-end verification remain local setup steps. See `VERIFIED.md` for actual results.
- A practical starting point is a Windows 11 x64 computer with enough free RAM for both local models; this guide discusses a roughly 32 GB configuration. CPU inference is the baseline; GPU/NPU acceleration and laptop latency have not been measured.

## 1. Windows setup

Use a private local folder outside OneDrive/Dropbox/shared drives, for example `%LOCALAPPDATA%\AIHandbookAssistant`. Respect your organization’s policy for locally processing internal documents and installing software. You may need IT approval on a managed laptop.

1. Install **64-bit Python 3.12** from [python.org](https://www.python.org/downloads/windows/) if it is not already available.
2. Install current **Ollama for Windows** from [ollama.com/download/windows](https://ollama.com/download/windows). Start the Ollama application.
3. Download or clone this repository as described above. Open PowerShell in the project folder containing `app.py`.
4. Create an environment and install the pinned direct dependencies:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

No PowerShell activation or execution-policy changes are needed. Always use `.venv\Scripts\python.exe` directly.

5. Disable Ollama cloud features before processing internal material. Set the user environment variable below, fully quit Ollama from the tray, and restart Ollama so it picks up the setting:

```powershell
[Environment]::SetEnvironmentVariable('OLLAMA_NO_CLOUD', '1', 'User')
```

Also keep Ollama bound to its default loopback host. Do not set `OLLAMA_HOST=0.0.0.0`. The application rejects remote Ollama URLs and cloud-tagged/non-local models, disables HTTP proxy inheritance, and makes no cloud inference calls. Disabling cloud at the Ollama service adds a second layer.

6. Download the two local models. This downloads model weights over the internet; your documents are not involved:

```powershell
ollama pull qwen3:4b
ollama pull qwen3-embedding:0.6b
ollama list
```

The published model downloads are approximately 2.5 GB and 639 MB. Allow additional disk space and RAM for runtime/context/indexes. Approximately 32 GB of system RAM makes the 4B default a reasonable starting point, depending on how much memory other applications are using. Close memory-heavy applications if needed and reduce context to 4096 under pressure. GPU acceleration is optional. The Intel NPU is not assumed to accelerate this setup. Initial model loading and CPU responses can take time. Both embedding and generation calls unload their model after use (`keep_alive=0`) to prioritize free memory over warm-start latency.

7. Optional Confluence credentials:

```powershell
Copy-Item .env.example .env
notepad .env
```

Enter your own approved tenant URL (`CONFLUENCE_BASE_URL`, in the form `https://your-company.atlassian.net/wiki`), numeric root page ID (`CONFLUENCE_ROOT_ID`), email, and API token **only in the local `.env` file**. Do not paste them into chat, source code, screenshots, or version control. Manual file import works without Confluence credentials. Restart Streamlit after editing `.env`.

8. Verify local models, then start the app:

```powershell
.\.venv\Scripts\python.exe check_setup.py
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

Open **http://127.0.0.1:8501** on the same computer. Stop with Ctrl+C. Keep the loopback binding; do not expose this app on a LAN, reverse proxy, or public hosting service. No login/access-control layer is included because this is a single-user local demo.

### macOS / Linux alternative

Install Python 3.12 and Ollama from their official sites, start Ollama with `OLLAMA_NO_CLOUD=1`, and use:


## 2. Ingest the real handbook

No organization-specific target is configured in this repository. Set `CONFLUENCE_BASE_URL` and `CONFLUENCE_ROOT_ID` in your private local `.env`, then restart the app. The sidebar link, sync scope, and citation links use that same validated tenant and root. Use a separate `DATA_DIR` for each unrelated tenant or handbook; changing the target does not automatically remove content you previously indexed. When these values are absent or invalid, no Confluence request is made; manual file import remains available.

The API importer expects published Confluence pages with a storage-format body. Drafts, live documents, and other content types may not be compatible. Use an authorized local export if the API route cannot retrieve your source. The importer has been tested with offline fixtures, not a live tenant.

### Confluence API route

The **Sync Confluence** button uses the official Confluence Cloud REST v2 APIs with email/API-token Basic authentication. It reads only the target page by default. Select the explicit options to include descendant pages and/or PDF, DOCX, TXT attachments. Child traversal follows direct page-child relationships; it does not crawl external links, other spaces, embedded pages, include macros, or arbitrary URLs.

Use an API token compatible with your tenant’s direct REST endpoint. Tokens requiring the scoped-token `api.atlassian.com` gateway are not supported by this demo; use a policy-approved compatible token or the export route. Never broaden token permissions just for this demo without IT guidance.

The client checks every pagination/download URL before sending credentials. It blocks cross-origin redirects, including attachment redirects to a CDN. If that affects an attachment, download/export it yourself and import the local file. This is a deliberate safety limitation, not proof that the attachment is missing. Transient requests retry a bounded number of times with rate-limit handling.

HTTP 401/403/404, inaccessible children, failed attachments, non-page containers, limits, and extraction failures are reported. A partial sync never implies that all handbook content was indexed. Dynamic macros are not resolved. Inspect the source inventory and warnings.

### Manual route

In Confluence, export/download an allowed HTML, PDF, DOCX, or UTF-8 TXT copy. Upload it under **Add handbook exports** and click **Index uploaded files**. For a ZIP export, extract it locally first and select the relevant HTML files; ZIP crawling and embedded attachment discovery are intentionally unsupported.

- Headings, paragraphs, list items, table cell text, and useful code blocks are retained as text. PDF layout and complex Word formatting may be imperfect; inspect important passages.
- Scanned or image-heavy PDFs with little extractable text are flagged. This app does not run OCR. Use a trusted local OCR tool or obtain a text-based export, then re-upload.
- Each file is limited to 25 MB, PDFs to 500 pages, DOCX expanded size to 100 MB, and extracted text to 2 million characters.
- Files with the same filename replace that manual source. Renaming a file creates a separate manual source. Avoid duplicate filenames for different documents. Identical repeat uploads do not add duplicate chunks. The prior same-filename source is quarantined before replacement; a failed import cannot silently keep the old text active.
- Manual exports are snapshots and do **not** inherit later Confluence permission or deletion changes. Re-export them when the original changes. To discard the local index and its contents, stop the app and delete the private `data` folder yourself; the next launch creates an empty index.

The raw upload is processed in memory; extracted document text, metadata, embeddings, and catalog are stored locally in `data/`. Do not commit, share, or upload this folder. It is not application-encrypted; use the laptop’s approved disk encryption and access protections.

## 3. Ask questions

### Handbook Q&A

Every question performs fresh embedding retrieval. Recent user questions help interpret follow-up references; previous assistant answers are never evidence. The model receives only the current retrieved passages, bounded history, and the question.

For stronger grounding, this demo deliberately uses **strict extractive answers**: Qwen3 selects relevant verbatim passages and returns structured source IDs. The application verifies each quote is an exact substring of a current retrieved passage, checks IDs, and assembles the answer with numbered citations. It does not display unsupported model-written summaries. Click each citation’s expander to read the supporting context and open the Confluence source. Manual exports have a local filename and downloadable supporting excerpt.

If there is no qualifying evidence, the model signals insufficient support, or returned evidence is invalid, the answer is exactly:

> I couldn’t find this information in the indexed documents.

This checks provenance, **not semantic truth**. A model may select a literal but irrelevant or misleading excerpt; documents may be wrong; retrieval may miss a relevant passage. Review the source before using an answer. A cosine similarity value is a retrieval score, not a confidence percentage. Prompt-injection text is treated as document data, never as instructions; no tools/actions/browsing are exposed to the model. Source text is displayed as plain text, so an embedded Markdown image does not automatically make a browser request.

### General Chat

This is a separate conversation using only the local model’s general knowledge. It does not retrieve indexed documents or pretend to be handbook-grounded. It can be inaccurate. **Clear Chat** clears both modes’ in-memory conversations. Chat history is not intentionally persisted by this app.

Starting a sync, rebuild, or file import clears the current session’s Handbook Q&A history so older source snapshots are not mistaken for the refreshed index. General Chat remains separate.

## 4. Sync, rebuild, and settings

- **Sync Confluence** re-fetches sources and compares text hash + metadata/version. Unchanged sources are reactivated without re-embedding. Changed sources replace their older chunks.
- Before remote verification begins, previous Confluence entries in the root scope are quarantined. Only freshly verified, successfully indexed sources become active. Authentication, traversal, extraction, indexing, or interrupted-sync failures leave unverified entries excluded from retrieval. Their cached text remains on disk until a complete refresh removes it or you delete local data.
- Missing/out-of-scope sources are pruned only after a fully successful bounded snapshot. Partial traversals cannot cause broad destructive pruning. Turning child/attachment options off and completing sync narrows the index to the selected scope.
- Between manual syncs, Confluence changes are not automatically detected. Sync before relying on freshness. Access is checked as the API-token account; there is no multi-user authorization model.
- **Rebuild Index** re-embeds active cached documents. It does not fetch Confluence or reactivate quarantined documents. Sync again to verify those sources.
- Changing embedding model or chunk settings creates a distinct collection and requires rebuilding. Also rebuild after re-pulling/replacing embedding weights under the **same model tag**. The collection fingerprint uses the tag and chunking configuration, not model weight digest.
- Defaults: 1600-character chunks, 200-character overlap, top 5 passages, cosine similarity ≥0.30, 8192-token context. Headings are preserved as chunk metadata; paragraph/line boundaries are preferred. Character counts are not token counts. Prompt assembly uses a conservative UTF-8 byte budget with space reserved for system text, schema, and output; the number of passages actually sent can be below top-k. If no passage fits, shorten the question, increase context, or reduce chunk size and rebuild. At 4096 context, 500–800-character chunks may work better. Tune after checking real handbook questions.
- Higher thresholds can miss valid evidence; lower thresholds can retrieve unrelated text. The structured quote check still applies. Increase context cautiously if memory allows. Configuration is available in `.env` and the sidebar; sidebar changes last for the current session.
- The sidebar shows model availability, active source count, quarantined count, stored chunk count, and last completely successful Confluence sync in UTC. Stored chunks can include excluded quarantine/orphaned generations; only catalog-active generations are searchable.

The source catalog commits active generations after embeddings are written. Retrieval filters against these catalog-approved generations. Old/orphaned chunks from interrupted writes are not used. A filesystem lock protects mutations/retrieval; treat the app as single-user, not a production database service.

## Troubleshooting

- **Ollama unavailable:** start its application/service; run `ollama list`; check that the host is loopback and no cloud model is selected. Restart after setting `OLLAMA_NO_CLOUD`.
- **Slow / out of memory:** close other applications, reduce context to 4096 and retrieved passages to 3; use a smaller downloaded local generation model if needed. Requests load weights as needed and unload afterward to reduce simultaneous memory pressure, so there is a reload cost.
- **Empty index or exact fallback:** inspect inventory and quarantine warnings; sync/upload first; verify the question is covered; check extraction; cautiously lower similarity. A fallback is not proof the underlying handbook lacks the answer.
- **401/403/404:** check token/email, expiry, tenant policy, and page permissions. Never share token values to troubleshoot. Use manual exports if approved API access is unavailable.
- **Attachment blocked:** off-origin CDN redirect or unsupported content; import an authorized local export.
- **Rebuild failure:** fix local Ollama/model/memory issue, then run Sync Confluence for quarantined Confluence sources or re-upload the manual file. Partially rebuilt data remains excluded until successfully indexed.
- **Python installation issue:** use Python 3.12 x64; install through your approved registry/network. Do not disable certificate verification or security software.
- **Managed network TLS/proxy issue:** this demo disables inherited proxies to prevent credential/evidence forwarding. Ask IT for an approved route or use manual export. Do not disable TLS verification.
- **Sensitive data handling:** `.gitignore` excludes credentials, document exports, uploads, databases, environments, and logs. It is defense in depth; review files before any future source sharing. Never send `data/` or `.env` with a bug report.

## Project map

`app.py` is the Streamlit UI. `handbook_assistant/confluence.py` handles bounded ingestion; `extract.py` extraction; `chunking.py` heading-aware chunks; `ollama_client.py` local inference; `store.py` persistence and source status; `rag.py` strict citations and separate general chat. Tests are in `tests/`. `.env.example` contains placeholders only. Direct runtime/dev dependencies are version-pinned and the tested environment passes `pip check`.
